# OA 官文汇报信分配流程与审核页说明

> 依据当前 `scripts/main.py`、`scripts/report/read_email.py`、`scripts/report/report_server.py` 和 `scripts/web/prototype.html` 整理。本文只描述**收到 OA 官文后是否分配汇报信、准备人审核及发给客户**；OA 立项人员分配页（`/oa-assign`）是另一条流程。

## 一、整体链路

```text
官文邮件
  → 读取并分类（地区、通知类型、案号、日期、期限、附件）
  → OA 汇报信规则判断（模板是否存在 → 客户/类型/次数匹配）
      ├─ assign：创建 report_tasks 待审核任务 → 发审核链接给准备人
      ├─ skip：不创建汇报信任务；规则配置了转发对象时转发原始官文邮件
      └─ ignore / 无匹配模板：不创建汇报信任务
  → 准备人打开 /review/{任务ID}，补充、核对字段和附件
  → 发送弹窗核对发件人、客户收件人、抄送、主题、附件
  → 人工确认发送客户邮件；成功后任务变为 done
```

`main.py` 对同批邮件只读取、分类一次，再分别送往 OA 立项和汇报信两个下游；汇报信侧是否运行由 `pipeline_config.json` 的 `sinks.report` 控制。**创建审核任务不等于已向客户发信**，客户邮件须在审核页人工确认。

## 二、输入

| 输入 | 来源 | 在汇报信流程中的用途 |
| --- | --- | --- |
| 原始官文邮件 | 邮箱：发件人、主题、正文、邮件 ID、原始字节及附件 | 识别地区和官文类型；按邮件 ID 关联附件；需要转发时保留原邮件 |
| 分类结果 | `classify_report.py` | 提供 `region`、`notification_type`、`project`（代理所案号）、发文日、期限、申请号、案件名称等；CN 审查意见从案件名称中的“第几次”分变体，EP R.71(3) 从主题分变体 |
| OA 汇报信模板映射 | atw `report_rule_template`（`rule_domain='oa'`） | 按地区＋通知类型确定模板文件名和是否默认附汇报信 PDF；无映射即不生成汇报信任务 |
| OA 汇报信分派规则 | atw `report_rule`（`rule_domain='oa'`） | 按地区＋类型/变体＋客户号（案号前 5 位）决定 `assign`、`skip` 或 `ignore`，以及准备人、原邮件转发对象 |
| 模板正文 | atw `report_template` | 审核页渲染所选 MD 模板；表中无有效正文时回退 `scripts/templates/md/` 下同名文件 |
| 案件和联系资料 | IPEasy 案件数据、atw 接口人/`report_recipient` | 打开审核页时补全案件字段和流程联系人；发送前按族号/客户号带出客户收件人和抄送 |

OA 规则优先读数据表并在当前进程内缓存；数据表为空或读取失败时回退 `scripts/report/oa_report_rules.json`。模板**选择**发生在任务创建时，所选模板文件名存入任务；模板**正文**在审核页打开时从 `report_template` 获取。规则表修改后，运行中的读取进程需要重新加载才能使用新分派规则。

## 三、分派判断与输出

1. **分类**：汇报信侧 CN 只接收 `xing.wu@metis-ip.com` 发来的匹配邮件；US 根据 USPTO 发件人/主题及正文中的官文类型识别；EP 根据指定发件人及主题中的官文名称识别。不满足分类条件的邮件不会进入该汇报信判断。
2. **模板门槛**：`region + notification_type` 必须在 OA 模板映射中。CN 审查意见按第一次/第二次及以后区分规则变体；EP `Intention to grant` 若主题含 R.71(3)，改按 R.71(3) 变体规则判断。
3. **客户匹配**：同一类型下，配置了 `*` 则所有客户直接采用该规则；否则依次匹配精确客户号、`5开头`、`其他`。未命中具体规则时走代码兜底：CN 案号以 5 开头跳过，其余已命中模板的任务可按默认准备人分配。
4. **动作**：`assign` 创建待审核任务；若规则含 `also_forward`，可同时转发原始官文。`skip` 不创建任务，若配置并解析到转发地址则转发原始官文。`ignore` 不创建任务，也不执行汇报信侧转发。

| 分支 | 系统输出 | 准备人/客户能看到什么 |
| --- | --- | --- |
| `assign` | atw `report_tasks` 新增 `pending` 任务，写入模板、字段 JSON、附 PDF 标志、源附件路径；生成 `/review/{任务ID}` 链接 | 按规则准备人收到审核链接通知；此时客户**未**收到汇报信 |
| `assign + also_forward` | 上述任务及原始官文转发 | 准备人仍审核汇报信；另有规则指定对象收到原始邮件 |
| `skip` | 不生成审核任务；若设转发对象则转发原始邮件 | 无汇报信审核页、无客户汇报信 |
| `ignore` 或无模板 | 不生成审核任务 | 无汇报信审核页、无客户汇报信 |
| 审核页“跳过” | 已有任务更新为 `skipped` | 不向客户发汇报信；与分派阶段的 `skip` 不同 |
| 审核页“确认发送”成功 | 客户邮件发出，任务更新为 `done` 并记录审核人 | 客户收到邮件及最终勾选的附件；失败时任务保持 `pending` 以便重试 |

分派邮件按准备人分组发送审核链接；规则指定的 `preparer` 优先，未指定时 CN 默认任惠、US/EP 默认王晶。没有准备人邮箱时不发送链接通知。源附件主要为原邮件官文 PDF；US 可采用 OA 立项侧已下载的官文 PDF；20608 案号还会在原有附件基础上补入原邮件的 ZIP/RAR/7Z 压缩包。

## 四、最终页面：汇报信审核与发送

**入口**：准备人点审核通知中的 `/review/{任务ID}`。这不是 OA 人员分配页，也不是规则维护页。页面从 `report_tasks` 读取任务、实时补案件资料，并按该任务的模板正文渲染预览。

```text
┌──────────────────┬────────────────────────────────────┬──────────────────────────┐
│ 左栏：待办列表      │ 中栏：汇报信字段与附件               │ 右栏：邮件正文预览           │
│ 案号/类型搜索      │ 客户要求（只读参考）                 │ MD 模板 + 已填字段          │
│ pending/skipped  │ 基本信息、申请信息、官文与期限        │ 刷新后核对最终内容           │
│ 选择一条审核任务    │ 接口联系方式、按法域显示的专用字段    │                          │
│                  │ 官文附件、手动上传附件               │                          │
│                  │ 刷新预览 / 确认发送 / 跳过 / 附 PDF   │                          │
└──────────────────┴────────────────────────────────────┴──────────────────────────┘
                          ↓ 点击“确认发送”后弹窗复核
                  发送人｜收件人｜抄送｜主题｜附件勾选｜确认发送
```

| 区域 | 具体构成 | 数据来源与可操作项 |
| --- | --- | --- |
| 页头、左栏 | 当前案号/类型/状态；待办列表和搜索 | `/api/tasks`；可切换任务 |
| 中栏基本信息 | 客户要求、案号、客户信息、申请信息、官文与期限 | 邮件分类结果＋IPEasy 案件资料＋已保存的 `fields_json`；审核人可修改适用字段 |
| 中栏联系人 | 接口人姓名、邮箱、手机 | atw `customer.bspeople` 对应 `users` 信息；默认首位，可下拉选择或手动编辑 |
| 中栏附件 | 官文附件列表；手动上传其他需随信发送的文件 | 原邮件/US 官文 PDF 等保存在任务源附件；上传文件保存在 `output/_manual/{任务ID}/` |
| 右栏预览 | 按 MD 模板和当前字段生成的邮件正文 | 模板占位符由字段替换；未使用的表单组按模板字段动态隐藏 |
| 底部操作 | 刷新预览、确认发送、跳过、附 PDF 汇报信 | 跳过仅更新已有任务；勾选 PDF 时可将汇报信 PDF 随邮件发送 |
| 发送弹窗 | 发送人、收件人、抄送、主题、附件 | 发件人默认按案号是否含 `-H` 选众慧/七星天，可改；收件人按族号前 10 位优先、客户号前 5 位回退，从 `report_recipient` 取 `to/cc`，仍无数据则 IPEasy 兜底；收件人可下拉多选及手填，抄送和主题可编辑；源附件与手动附件逐项勾选 |

**发送后的产物**：确认时按案号把可选汇报信 PDF 和邮件 `.eml` 备份写到 `scripts/output/{代理所案号}/`；SMTP 成功才把任务置为 `done`，失败保留 `pending`。模板正文、客户收件人、抄送与发件人是在审核/发送阶段确定的，不能把“已分配审核链接”理解成“已给客户发信”。
