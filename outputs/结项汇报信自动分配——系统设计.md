## 一、总体思路

结项汇报信自动分配**不新建独立系统**，而是把"结项"作为汇报信分配的**第二个规则域**（`rule_domain='close'`），接入已有的汇报信管道：

- 触发在 TIP 结项页的发送链路（`/manage/sendmailcloseproject`）里，**结项邮件发出成功后**追加一次分配判断与抄送；
- 分配判断、任务创建、审核页、发送链路**复用 OA 官文汇报信的既有实现**，只做两处扩展：① 任务表加 `rule_domain` 分域；② 规则与模板读数据表（`report_rule*` / `report_template`）。
- 结项与 OA 的差异（无原始邮件、抄送语义、匹配键）收敛在**规则域分支**里，不污染公共流程。

## 二、模块划分与协作

| 模块 | 职责 | 与谁协作 |
|---|---|---|
| **触发接入层**（TIP 结项发送链路） | 现有 `/manage/sendmailcloseproject` 保存结项记录 + 发结项邮件；发信成功后调用分配入口；把规则抄送并入结项邮件抄送 | 调用「结项分配器」；复用现有结项邮件发送 |
| **结项分配器**（新，`close` 域入口） | 判断是否分配：法域 → 结项类型 → 客户；命中动作后创建任务或产出抄送列表；防重复 | 读「规则与模板仓储」；写「任务仓储」；返回抄送列表给触发接入层 |
| **规则与模板仓储**（扩展，读数据表） | 按 `rule_domain='close'` 读 `report_rule_map` / `report_rule_template` / `report_rule` / `report_template`；进程内缓存 | 被「结项分配器」与「审核页」调用 |
| **任务仓储**（扩展 `report_tasks`） | 任务 CRUD；`id` 为独立 UUID（与 `projects.id` 无绑定），`rule_domain` 分域；按域查询待办 | 被「结项分配器」「审核页 API」调用 |
| **审核与发送模块**（复用三栏页 + API） | `/review/{任务ID}` 三栏页、`/api/tasks`、模板渲染、确认发送/跳过、附件、发送备份 | 读「任务仓储」「规则与模板仓储」；发客户邮件 |
| **审核链接通知**（复用） | 按准备人邮箱分组发审核链接 | 被「结项分配器」触发 |

协作主线：**TIP 结项发送 → 结项分配器 → （读规则仓储判断）→（写任务仓储 / 产出抄送）→ 结项邮件（含抄送）发出 → 通知准备人 → 准备人在三栏页审核 → 确认发送 → 任务 done**。

## 三、数据流

### 3.1 触发与分配

```text
流程人员在 TIP 结项页点"发送"
  → 保存结项记录（projects_close / tip_bill_submit / tip_bill）
  → 结项分配器执行：
      1) 取案号 → 法域判定（含 EP/US/WO/CN，其余不处理）
      2) combination = cls_task_1 + cls_task_2 → 经 report_rule_map 得 rule_key
      3) 客户码 = 案号前 5 位 → 按 精确 → 5开头 → 其他 → * 匹配 report_rule
      4) 防重复：存在同「案号 + 结项类型」的结项任务 → 不重复创建
  → 命中 assign：创建结项任务（rule_domain='close'）→ 生成 /review/{id}
  → 命中 skip：产出抄送列表（发件人并入抄送，to+cc 全并 cc）
  → 命中 不处理/未命中：不产出
  → 结项邮件发送（含 skip 的抄送；不处理不抄送）
  → 邮件发出成功：正式落库任务 / 发审核链接
     邮件发出失败：不创建任务、不抄送（原子回退）
```

### 3.2 审核与发送

```text
准备人点审核链接 → /review/{id}（三栏页）
  → 读任务（含 rule_domain='close'）＋ 模板正文（report_template，回退 templates/md/）
  → 补案件资料（IPEasy/atw）→ 右栏渲染正文；中栏附件暂空、可手动上传
  → 确认发送 → 弹窗复核收件人/抄送/主题/附件 → SMTP 成功 → 任务 done，备份 .eml
  → 点跳过 → 任务 skipped
```

### 3.3 关键取数口径

| 数据 | 来源 |
|---|---|
| 案号、结项类型、客户 | TIP 结项页提交的表单 + 案件查询（`proQuery`） |
| 结项类型映射 | `report_rule_map`（`rule_domain='close'`：combination → 结项类型） |
| 模板与是否附 PDF | `report_rule_template` |
| 动作/准备人/抄送 | `report_rule`（客户优先级：精确 → `5开头` → `其他` → `*`） |
| 模板正文 | `report_template`（回退 `templates/md/`） |
| 准备人邮箱、抄送邮箱 | 数据表（均为邮箱地址，无人物名映射） |

## 四、AI 调用

**本功能不涉及 AI 调用**：法域判定、结项类型映射、客户匹配、动作选择均为确定性规则匹配（读数据表），无需模型推理。模板正文由字段占位符替换生成，无生成式环节。

（如后续需要在结项场景生成正文措辞，再作为独立事项评估；第一阶段不做。）

## 五、状态管理

### 5.1 结项任务状态（沿用 OA 汇报信语义）

| 状态 | 含义 | 进入方式 |
|---|---|---|
| `pending` | 已创建、待审核/发送 | 命中 `assign` 创建；发送失败退回 |
| `skipped` | 审核页人工跳过 | 审核页点"跳过" |
| `done` | 已向客户发送成功 | 审核页确认发送、SMTP 成功 |

规则域的 `skip`（不分配）**不创建任务**，与审核页的 `skipped` 语义不同。

### 5.2 分域

- 任务带 `rule_domain`（`oa` / `close`）；审核页与 `/api/tasks` 按域过滤；
- 同一案件多阶段任务因 `id` 为独立 UUID 而各行独立，不覆盖。

### 5.3 防重复

- 判定键：**案号 + 结项类型**；存在同键结项任务即不再创建。

### 5.4 规则缓存

- 规则表读入进程内缓存；规则修改后运行进程需重载方可生效（沿用现有 OA 侧行为，写进运维注意）。

## 六、界面与后端映射

| 界面（复用/新增） | 后端 | 说明 |
|---|---|---|
| TIP 结项页 `/manage/proccloseproj`（现有，不改填写逻辑） | `/manage/proQuery`、`/manage/addPro`、`/manage/sendmailcloseproject`（现有） | 仅在其发送链路中追加"分配入口 + 抄送并入" |
| 三栏审核页 `/review/{任务ID}`（复用） | `/api/tasks`（按 `rule_domain` 过滤）、任务读取、模板渲染、确认发送/跳过、附件上传（现有） | 结项任务复用同一页；中栏附件暂空 |
| 发送弹窗（复用） | 收件人/抄送/发件人取数 + SMTP 发送 + `.eml` 备份（现有） | 收件人/抄送按结项任务数据出 |
| 审核链接通知（复用） | 按准备人邮箱分组发送 | 结项任务同机制 |

新增/改动点：TIP 结项发送接口内的**分配调用**；`report_tasks` 的 **`rule_domain`**；规则仓储的 **`close` 域读表**；`/api/tasks` 的**按域过滤**。

## 七、技术选型

沿用既有系统技术栈，不引入新框架：

- **后端**：现有 Python（TIP 结项页 `managesys/procedure_manage.py`；汇报信侧 `scripts/report/*`：`rules_store.py`、`read_email.py`、`report_server.py`、`enrich_report.py`）；
- **数据库**：MySQL / atw；复用 `report_tasks`、`report_rule*`、`report_template`（模板正文入库方案 B）；
- **前端**：现有模板页面（`templates/procedure_closeproj.html`）与三栏审核页（`scripts/web/prototype.html`）；结项复用三栏页，不新增前端框架；
- **邮件**：现有 SMTP 发送与 `.eml` 备份机制；
- **规则/模板**：读数据表，缓存于进程内。

## 八、可复用资产梳理

| 资产 | 复用方式 |
|---|---|
| OA 官文汇报信分配链路（分类→规则→任务→通知） | 结项作为第二规则域接入，复用任务/通知/审核/发送 |
| 三栏审核页 + 发送弹窗 + `/api/tasks` | 直接复用，仅加按 `rule_domain` 过滤 |

| 规则仓储与进程内缓存 | 扩展支持 `close` 域 |
| SMTP 发送 + `.eml` 备份 | 直接复用 |
| `report_recipient` 收件人表 | 可复用于结项收件人/抄送配置 |
| 结项邮件发送链路（现有） | 复用其发送，仅追加分配调用与抄送 |

## 九、风险与注意点

- **原子性**：分配判断须挂在"结项邮件发出成功"之后；发信失败不得留任务、不得抄送——实现上以"邮件成功回调/先后判断"保证。
- **抄送合并**：`skip` 的 to+cc 全并进 cc，发件人并入抄送栏；须与现有结项邮件收件人（`patents_pa@`）和抄送（`docketing@`）合并去重。
- **多阶段并存**：`report_tasks.id` 与 `projects.id` 均为独立 UUID，OA 侧无 `id=projects.id` 假设，无需兼容改造。
- **缓存刷新**：规则表更新后需重载进程，运维需知会。
- **附件暂缺**：中栏附件暂空，结项汇报信发送初期需人工上传或后续补齐来源。
