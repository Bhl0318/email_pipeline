> 版本：v1.0（2026-10-08）
> 说明：第 1、2 部分为整理后的正式需求；第 3、4 部分为本次澄清过程原始记录。另有「-无过程记录版」只保留第 1、2 部分。
> 需求主次：**主要需求**来自《结项通知页面功能说明》（触发点）、**口头记录**（"在 TIP 结项的时候，自动分配结项汇报信"）与《结项类汇报信规则》（分配规则）；**既有机制基线**为《OA 官文汇报信分配流程与页面说明》（现有分配、审核、发送链路）；**参考文件**为《汇报信规则数据表设计》（规则读表的表结构依据）。

## 1. 需求概述

在 **TIP 结项**时，系统自动判断该案件应否生成**结项汇报信**，并按规则完成分配：

- 流程人员在 TIP 结项页（`/manage/proccloseproj`）填写结项信息并点"发送"；
- 系统在**结项邮件发出成功**后，按**结项类型 + 客户**匹配结项汇报信规则；
- 规则命中 `assign`：创建结项汇报信**审核任务**并把审核链接发给准备人；
- 规则命中 `skip`：不创建汇报信任务，但把**结项邮件抄送**给规则指定的人（发件人也并入抄送栏）；
- 规则命中 `不处理`（`ignore`）：不创建任务、不抄送，**结项邮件照常发**。

结项汇报信的审核与发送**复用现有三栏审核页**（`/review/{任务ID}`），与 OA 官文汇报信共用同一套审核、发送机制。

第一阶段范围：**只做结项类汇报信的自动分配**，不改变 TIP 结项页本身的填写与保存逻辑；规则与模板正文**读数据表**。

## 2. 需求详述

## 2.1 触发与时机

- **触发点**：TIP 结项页点"发送"（`/manage/sendmailcloseproject`）时。
- **时序**：**先**完成结项记录的保存与结项邮件发送；**结项邮件发出成功后**，才执行汇报信分配判断与抄送动作。
- **原子性**：结项邮件发送失败（页面提示 `sendfailed`，记录已存但邮件未发）时，**不创建汇报信任务、不做规则抄送**——两项与"结项邮件发出成功"视为一个原子动作。
- **防重复**：同一案件**不可重复分配**；重复点击发送/重复结项时不产生重复的汇报信任务。

## 2.2 分配判断

按"**法域 → 结项类型 → 客户**"逐层判断，全部依据**数据表**中的规则：

1. **法域判定（按案号）**：案号含 `EP`→EP；含 `US`→US；含 `WO`→PCT；含 `CN`→CN；**其余（CM/CS/DS/DM/商标等）→ 不处理（skip 不发）**。
2. **结项类型匹配**：以 TIP 结项任务的 `combination`（= `cls_task_1` + `cls_task_2` 的拼接，即页面"结项类型"）去对上规则的"结项类型"；**命不中任何行 → 默认不处理（skip 不发）**。
3. **客户匹配**：客户码取**案号前 5 位**（"5开头"判定为**案号第一位为 5**）；依次匹配精确客户码 → `5开头` → `其他` → `*`。

## 2.3 三种动作与输出

| 规则动作 | 系统输出 | 结项邮件 |
|---|---|---|
| `assign`（分配→X） | 创建结项汇报信审核任务；审核链接发给准备人 X | 照常发出；按规则抄送 |
| `skip`（不分配→a 抄b） | 不创建汇报信任务 | 照常发出；**抄送**规则指定的人（发件人 a 并入抄送栏，to+cc 全并进 cc） |
| `不处理`（ignore） | 不创建汇报信任务、不抄送 | **照常发出**，不抄送任何人 |

- 抄送对象一律以**数据表中的人员邮箱**为准。
- `skip` 分支依赖结项邮件发出成功；失败则不做抄送（见 2.1 原子性）。

## 2.4 审核与发送（复用既有机制）

- 结项汇报信任务复用现有**三栏审核页** `/review/{任务ID}`：左栏待办列表、中栏字段与附件、右栏邮件正文预览；底部操作为刷新预览 / 确认发送 / 跳过 / 附 PDF。
- 任务类型/状态字段与现有 OA 汇报信**保持一致**（`pending` / `skipped` / `done`）。
- 结项场景**没有原始官文邮件**：中栏附件来源**暂为空，后期补充**；模板正文按任务所选模板渲染。

## 2.5 任务标识与多阶段共存

`report_tasks.id` 与 `projects.id` 是各自独立的 UUID，同一案件不同阶段的任务天然各行独立，不存在覆盖问题，**主键与关联列均无需改动**。本期仅需：

- **新增 `rule_domain` 列**（`oa` / `close`）区分汇报信来源；
- 审核页与 `/api/tasks` 按 `rule_domain` 过滤，OA 与结项任务互不干扰；
- **防重复判定键**：项目 + 结项类型（项目即案号），按「案号 + 结项类型」判重。

## 2.6 规则与模板来源

- 结项分配**读数据表**：规则、模板名与模板正文均以数据表为准（对应《汇报信规则数据表设计》中的 `report_rule_map` / `report_rule_template` / `report_rule` / `report_template`）。
- 规则匹配键：结项类型经「组合 → 结项类型」映射（`report_rule_map`）后落到 `report_rule`。
- 模板正文取 `report_template`；查不到再回退 `templates/md/` 文件。

## 2.7 第一阶段范围

第一阶段明确：

- 只做**结项汇报信的自动分配**；
- 规则与模板**读数据表**；
- 审核与发送**复用三栏页**，不新做结项专用审核页；
- 不改变 TIP 结项页的填写/保存逻辑，只在其"发送成功"后追加分配与抄送；
- 分配与抄送**与结项邮件发送同属一个原子动作**（发信失败都不做）；
- **防重复分配**。

## 2.8 系统职责边界

本系统负责：

1. 在结项邮件发出成功后，按数据表规则判断法域、结项类型、客户；
2. 命中 `assign` 时创建审核任务并通知准备人；
3. 命中 `skip` 时把结项邮件抄送给规则指定人员；
4. 提供与 OA 汇报信一致的审核、发送链路（复用三栏页）；
5. 防重复分配与任务标识管理。

本系统**不负责**：

- TIP 结项页的填写、案件查询/新增与结项记录保存（沿用现有实现）；
- 结项邮件本身的正文与发送（沿用现有实现，仅追加抄送）。
