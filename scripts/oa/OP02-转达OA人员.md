# 转达 OA 人员

## 概述

将需要实质答复的 CN / US / EP 官文转给 OA 处理人员，以便安排 OA 答复。

**本操作覆盖三个法域：**
- 🇨🇳 **CN** — 需答复的 CNIPA 官文
- 🇺🇸 **US** — 需答复的 USPTO 官文
- 🇪🇺 **EP** — 需答复的 EPO 官文

---

## 1. 前置步骤：判断滴滴案件是否已结案

**仅滴滴客户（案号前缀 `20615-`）需要执行此步骤。**

### 1.1 当前方案

查询唯德系统中该案的状态：
- **状态 = 已结案** → 无需转 OA，不执行后续步骤，标记"滴滴已结案，跳过"
- **状态 = 未结案** → 继续执行转 OA

### 1.2 优化方案（建议）

将滴滴所有已结案案件的清单导出为结构化数据（如 CSV / JSON），由系统自动判断：

```
系统判断流程：
1. 提取案号
2. 在滴滴结案清单中匹配
3. 匹配到 → 跳过（已结案）
4. 未匹配到 → 继续转 OA
```

**优势**：无需每次查唯德系统，完全自动化。

> **待补充**：滴滴结案清单的维护方式（定期导出？系统接口？）

## 2. 输入信息

### 2.1 通用输入项

| 输入项 | 来源 | 说明 |
|--------|------|------|
| 案号 | 原邮件主题 | 主题格式因法域而异 |
| 官文类型 | 原邮件主题 / 附件 | 用于判定是否属于需转 OA 的类型 |
| 法域 | 案号后缀判定 | CN / US / EP |
| 发文日 | 原邮件主题或官文 | 官文发出的官方日期，期限计算起点 |
| 答复期间 | 各法域规则不同，见下方说明 | CN: 从邮件正文正则提取；US: 走USPTO API下载PDF解析；EP: 从正文 `within X months` 提取 |
| 截止日期 | 发文日 + 期限 | 计算获得 |
| 客户身份 | 从案号提取客户前缀 | 确定收件人中的客户公共邮箱 |
| 客户接口人 | TIP 系统 | 唯德 → 客户管理 → 客户编辑查询 → 输入客户代码 → 咨询与接口 |
| 官文 PDF 附件 | 原邮件附件 | 转 OA 必须附件 |

### 2.2 答复期限说明（按法域）

各法域 OA 的答复期限可从以下途径获取：

| 法域 | 期限获取方式 | 加速类型处理 |
|------|-------------|-------------|
| **CN** | 官方通知正文（含期限说明）或原邮件（转发人员的邮件正文应包含答复期限） | 优审通知正文已含期限（如"答复期限：2个月"），按正文规则提取即可。预审案件原邮件正文会注明"预审案件"并写明答复期限（如"答复期限：10个工作日"），按原文期限提取 |
| **US** | 从 USPTO 官文 PDF 获取答复期限 | 无加速类型区分 |
| **EP** | 从 EPO 官文（如 Art.94(3) 等）正文提取 `within X months` | 无加速类型区分 |

### 2.3 各法域需转 OA 的官文类型

#### CN

| 编号 | 官文类型 |
|:----:|---------|
| 1 | 第一次审查意见通知书 |
| 2 | 第二次审查意见通知书 |
| 3 | 第N次审查意见通知书 |
| 4 | 补正通知书 |
| 5 | 驳回决定 |
| 6 | 复审通知书 |
| 7 | 复审请求补正通知书 |

> 办理登记手续通知书不转OA（非OA，转办登缴费流程）。

#### US

| Document Type | 官文名称 |
|:------------:|---------|
| **CTNF** | Non-Final Rejection |
| **CTFR** | Final Rejection |
| **CTAV** | Advisory Action |
| **CTRS** | Requirement for Restriction Election |
| **EXIN** | Examiner Interview Summary Record |
| **CTEQ** | Ex Parte Quayle Action |
| **PPH.DECISION** | PPH Decision Dismissed |
| **NT.CR.APP.PA** | Notice to File Corrected Application Papers |
| **M327** | Notice to File Corrected Application Papers |
| **NTC.MISS.PRT** | Notice to File Missing Parts of Nonprovisional Application |
| **PETDEC** | Petition Decision Dismissed |

> NOA（Notice of Allowance）不转OA（转办登缴费流程）。ISSUE.NTF、892、1449、COCX 等非 OA 通知不转。

#### EP

| 编号 | EPO 通信类型 |
|:----:|-------------|
| 1 | European search report（欧洲检索报告） |
| 2 | Communication A.94(3) EPC（审查意见通知书） |
| 3 | Summons to oral proceedings（口审邀请） |
| 4 | Communication R.70(2) & 70a(2) EPC（合并至 EESR 转达） |

> Intention to grant（Rule 71(3)）不转OA（转办登缴费流程）。Further search fee、Communication R.62a(1) 不转OA。

## 3. 执行步骤

### 3.1 计算期限

根据法域和官文类型，从官文（正文 PDF 或原邮件）中提取答复截止日期，输出格式：

```
该官文的答复期限为[期限]，即[截止日期]。
```

**示例（CN 普通一通）：**
```
该官文的答复期限为4个月，即2026-11-22。
```

**示例（US CTNF）：**
```
该官文的答复期限为3个月，即2026-10-22。
```

**示例（EP Art.94(3) 审查意见通知书）：**
```
该官文的答复期限为4个月，即2026-11-22。
```

### 3.2 确定收件人

#### 3.2.1 收件人团队（固定人员）

所有法域的转 OA 收件人固定包含以下人员，再拼接对应客户的公共邮箱：

```
收件人：
  Jiao Yang（杨姣）<jiao.yang@metis-ip.com>;
  Jialu Bo（薄佳璐）<jialu.bo@metis-ip.com>;
  [客户公共邮箱]（根据案号前缀匹配，见客户公共邮箱对照表）
```

#### 3.2.2 客户公共邮箱

在收件人中补充对应客户的公共邮箱，对照表见 [客户公共邮箱对照表](./P1-客户公共邮箱对照表.md)：

```
  [客户公共邮箱]（根据案号前缀匹配，见客户公共邮箱对照表）
```

### 3.3 确定抄送人

#### 3.3.1 通用抄送人

所有法域统一：

```
抄送：
  Meixin Wu（伍美欣）<meixin.wu@metis-ip.com>;
  Min Zhao（赵敏）<min.zhao@metis-ip.com>;
  Jingjing Li（李晶晶）<jingjing.li@metis-ip.com>;
  Qiqi Yang（杨琪琪）<qiqi.yang@metis-ip.com>;
  OA立项 <oa@metis-ip.com>;
  Ya Su（苏雅）<ya.su@metis-ip.com>;
  Juanjuan Yao（姚涓涓）<juanjuan.yao@metis-ip.com>;
  [客户接口人]（从 TIP 系统获取）
```

**客户接口人获取方式**：唯德系统 → 客户管理 → 客户编辑查询 → 输入客户代码 → 咨询与接口。此环节由 IT 实现接口对接，流程规则上只需知道从 TIP 系统取即可。

### 3.4 发送邮件

#### 3.4.1 邮件主题

**保留原触发邮件主题**，不做修改。

#### 3.4.2 邮件正文模板

```
诸位好，

题述申请收到了[官文类型]，详情请见附件。该官文的答复期限为[期限表述]。

案号：[案号]
发文日：[发文日]
截止日期：[截止日期]

@OA 分析师值班人，请重启项目，生产管理安排人员处理。

--
发送人：张琴
```

> ⚠️ **待确认**：US/EP 的 OA 转达正文是否需要在内容或语言上有区别（如英文模板？）。

#### 3.4.3 附件

- **CN 官文**：附带官文 PDF
- **US 官文**：附带 USPTO 官文 PDF
- **EP 官文**：附带 EPO 官文 PDF

## 5. 变量清单

| 变量 | 含义 | 来源 |
|------|------|------|
| 法域 | CN / US / EP | 案号后缀判定 |
| 官文类型 | 如"第一次审查意见通知书" | 见上方 2.3 各法域类型清单 |
| 加速类型 | CN: 普通/优审/预审 | 原邮件正文注明（预审案件会标明"预审案件"） |
| 期限 | 如"4个月" | CN: 官文正文期限或原邮件；US: 官文PDF；EP: 官文正文 `within X months` |
| 截止日期 | 如"2026-11-22" | 发文日 + 期限 |
| 客户公共邮箱 | 不同客户对应 | 客户公共邮箱对照表 |
| 客户接口人 | 不同客户对应 | 从 TIP 系统（唯德）客户管理→客户编辑查询→输入客户代码→咨询与接口 |

## 7. 边界条件 / 异常处理

| 情况 | 处理方式 |
|------|---------|
| 滴滴客户案件在唯德中查不到状态 | 按"未结案"处理，标记"状态待确认" |
| 滴滴结案清单尚未维护 | 回退到逐案查询唯德 |
| 无法确定客户公共邮箱 | 仅发固定收件人，标记"客户公共邮箱缺失" |
| 无法确定客户接口人 | 不添加该抄送人，标记"客户接口人缺失" |
| 无法计算截止日期 | 写"截止日期待确认" |
| 无法确定加速类型 | 按"普通"处理，标记"加速类型未确认" |
| 没有 OA 分析师值班人 | 不@任何人，直接发邮件 |
| US 官文需要计算延期费 | 记录延期费用信息供参考，不代客户作延期决定 |
| EP 官文期限不可延期 | 邮件中突出标注"不可延期" |
